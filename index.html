8 merged 8 open Open-source LLM inference and fine-tuning

Some bugs I hit myself, others came from open issues. The GPU ones were reproduced on my own cards before the fix. Microsoft's onnxruntime repository has been unavailable since about 17 November 2026, so those links go to the same commits on my fork.

Merged: inference
  • ORT #33945 attention read a GPU-computed length as 0. The value sat in host-readable memory tagged as a GPU device, and a helper trusted only the CPU tag. With a static KV cache the output was wrong with no error. Four new tests fail without the fix.
  • ORT #33744 training-enabled CUDA builds load again. Eight missing cuDNN stubs made every session fall back to CPU silently on Linux. On Windows the same gap broke the link.
  • ORT #34081 graph-cache key zeroed before hashing. Nine padding bytes were hashed as they were, so equal keys could miss the cache and build a graph twice. Reproduced on release 1.31.0; latent on main. The duplicate build was first reported by john-rocky.
  • llama.cpp #30229 CPU and GPU agree on rounding under MSVC. One line. Nine of 18 f16/bf16 tests failed before it on the RTX 5070 Ti.
Merged: fine-tuning and tooling
  • Unsloth #7605 4 GB VRAM QLoRA guide and script. Run end to end on a GTX 1650. Writing it turned up two trainer-argument problems that the script now handles.
  • Unsloth #12839 LAN access binds only the addresses you choose. A security default. The maintainer extended it before merging.
  • Unsloth #13117 clear error when a pre-cast text encoder fails, in place of a confusing cascade.
  • Unsloth #13023 spell-check setting.
Open, not merged
  • mistral.rs #2539 FP8 quantization with CUDA graphs and concurrent requests. A cuBLASLt query during graph capture invalidated the capture; batch folding broke two requests at once. Not reviewed yet.
  • Ollama #19393 VRAM prediction counted CPU-resident tensors, which evicted models that would have fit. Prediction 6.8 to 5.4 GiB in my test.
  • Ollama #18978 retry startup with eager CUDA module loading. Low commit charge, not low RAM, caused the crash: 5 of 9 loads crashed on stock, 0 of 9 patched.
  • Ollama #19339 interrupted downloads resume after a restart.
  • Others Ollama #19496 and #18951; ONNX Runtime #33424 (changes were requested; state as of the last check, upstream is offline); Unsloth #12857.

Work in progress Ascend AI Tutor: RAG for Indian government exams

Personal project. Not launched, no users, no live demo. On main today: sentence-aware chunking, embeddings in ChromaDB, hybrid ranking with a keyword fallback, one async client for three LLM API styles with retries, token streaming, a context budget that keeps the system prompt and evidence pinned, and CI.

Known problems, and how I plan to deal with them
  • Data The corpus is placeholder data: 200 rows, 54 distinct questions, no sources. Replace it with sourced or clearly synthetic items, and fail ingestion on near-duplicates.
  • Eval Answer and retrieval quality are unmeasured. 50 labelled questions, hit@5 and MRR, vector against keyword against hybrid, run in CI. No quality number is published before a script reproduces it.
  • Retrieval Keyword overlap is weak. BM25 with rank fusion and a cross-encoder reranker are on a branch. They merge only if they beat the baseline.
  • Grounding A prompt does not stop hallucination. Cite chunk ids, check that they exist, abstain below a threshold, and test on unanswerable questions.
  • Output Malformed quiz JSON becomes a fake question. Schema-validated output with bounded retries is on a branch.
  • Safety Regex injection checks are easy to bypass. Treat retrieved text as untrusted, check outputs, keep a regression set of attacks.
  • Uptime Provider failure, hung queries, dropped streams. Fallback model, query timeout and stream replay are on a branch, with tests.
